# AI エージェント向け Processing

## 目的と設計

qtaro の既存の Processing カタログ検出とバックグラウンド実行から、国土数値情報を探し、取得し、地図・解析へ渡せるようにする。Python 3.9以上・QGIS 3.40以上を対象とし、依存関係は追加しない。

取得と読み込みを一体化する案では、SHP/GML の重複や複数レイヤーを意図せず追加してしまう。複数レイヤー出力のみの案では、qtaro の `BackgroundProcessing` が結果をプロジェクトへ移せない。そのため、次の4アルゴリズムへ分離する。

- `ksj:search_datasets`: 同梱索引を検索。`QUERY`（空白区切りAND）、`CATEGORY`、`EDITION`、`LIMIT`、`OFFSET`。JSON文字列 `RESULTS` と総件数 `TOTAL` を返す。
- `ksj:list_resources`: `DATASET_ID`、`YEAR`、`REGION`、`FORMAT`、`QUERY` で配布を絞り込み、同じページング出力を返す。URLから安定した `resource_id` を付与し、公式説明・年度・地域・形式・元のメタデータを保持する。
- `ksj:download_resource`: `DATASET_ID`、`RESOURCE_ID`、`DIRECTORY`（省略時は既存設定）で1配布を保存・展開する。ダイアログは使わず、未設定なら明確なエラー。`RESULTS` JSON にローカルレイヤーの `source`、`provider`、`name` と取得元を返し、`LOCAL_PATH` も返す。
- `ksj:load_layer`: 上記の `SOURCE`、`PROVIDER`、任意の `NAME` から1レイヤーを生成。`QgsProcessingOutputMapLayer` の `OUTPUT` を返す。qtaro はこの出力をプロジェクトに追加し、後続処理はレイヤーIDで参照できる。

検索はオフライン、取得は既存の `ensure_local_data` を利用。選択した配布だけを取得し、キャンセルを伝播する。サブレイヤーを列挙し、読み込めないファイルは警告とJSONに残す。空間参照・属性を保持し、投影変換・地物の切り抜きは既存の QGIS 解析へ委ねる。プロバイダ登録は `initProcessing` と `initGui` の重複呼び出しに耐え、unloadで解除する。qtaro リポジトリへの変更は不要。

## 検証上の重点

ページングで候補が欠落しないこと、旧形式の地域/年度が空でも例外にならないこと、同じ配布の再利用、取得中止時にレイヤーを残さないこと、サブレイヤー名・CRS・属性を保って解析へ渡せることを確認する。実機は QGIS 3.42.1 / Qt 5.15.2。QGIS 4 / Qt 6 の実機互換性はこの環境では主張しない。

## 実装時の判断

- 現在の作業ディレクトリで変更し、コミット・ブランチ変更・qtaroへの書き込みは行わない。
- ページサイズは既定20、上限100。エージェントの出力を抑えつつ `next_offset` で全候補を取得できる。
- ダウンロード成功とレイヤーとしての対応可否は別に報告する。旧形式等で読み込めない場合は `layers=[]` と警告を返し、原本の取得成功を失敗扱いしない。
- `QgsRasterLayer.LayerOptions` と `QgsVectorLayer.LayerOptions` のコンストラクタ差は、共通のデフォルト構築と `transformContext` プロパティ設定で吸収した。ラスタの回帰テストで失敗を確認して修正した。
- 検索語の推測変換は行わず、部分一致の契約を維持する。実カタログの表記揺れへの対処をREADMEへ追記した。

最終結果は [検証記録](verification.md) を参照。

## 追加改善: 選択式の入力画面

デスクトップ利用者がIDやURIを調べず操作できるよう、通常のProcessingダイアログを拡張する。既存の文字列パラメータとバッチ・モデル・Python実行の契約は維持する。

- データセットは分類・名称・版を表示する検索可能な選択欄。
- 検索の分類・版、配布一覧の年度・地域・形式はカタログ由来の候補。データセット変更時に従属項目を更新し、古い値を残さない。
- 取得の配布選択は年度→地域→形式の絞り込みと、ファイル名・測地系等の識別情報を表示。未選択で任意のファイルを取得しない。
- 読み込み元はファイル選択とサブレイヤー選択。読み込み方式はベクタ／ラスタとして表示し、ファイル選択で連動する。
- GUIコードは画面を開くときだけ読み込み、GUIなしの実行を維持する。
- 実Processingダイアログで値の変更・復元・実行パラメータ生成をテストし、画面を保存して確認する。READMEは一般利用者向けに書き換える。
