# Processing から現行機能を利用する

利用者の依頼は、ZIP 部分取得を必須として現行機能を Processing に公開し、Mapsuke から快適に呼べるようにすること。推奨範囲と詳細設計・実装の一任を承認済み。

## 方針と代案

部分取得だけを既存アルゴリズムに加える最小案と、一覧・一時取得・直接レイヤー出力・メッシュ索引まで公開する案を比較し、後者を採用する。既存の通信・保存実装を使い、Mapsuke 側の変更は不要にする。kumoy は無効のままとする。

## API

- `ksj:list_resource_files`: DATASET_ID / RESOURCE_ID から ZIP の目次を部分取得。QUERY / LIMIT / OFFSET、任意の DIRECTORY に対応。RESULTS に member、provider、部分取得可否と理由、出典を含める。圧縮された入れ子 ZIP と VRT は全体取得が必要と案内する。
- `ksj:download_resource`: 既存 ID・入出力を維持。任意の MEMBER を指定した場合はそのレイヤー一式のみ取得。空欄なら従来の全体取得。TEMPORARY を追加し、明示時は保存先設定不要。省略時の既存動作は変えない。
- `ksj:load_resource`: 同じ配布 ID と MEMBER から取得・読み込みを一度に実施。ZIP では MEMBER 必須。一時取得を既定にし、`SUBLAYER`で複数レイヤー形式の対象を選べる。省略時は選択ファイル内の全サブレイヤー。ENCODING は既存 `load_layer` と同じ。標準の複数レイヤー出力 `LAYERS` を返し、Mapsuke が GUI スレッドで所有権を引き取れるようにする。
- `ksj:create_mesh_index`: DATASET_ID と YEAR / REGION / FORMAT / QUERY で配布を絞り、配布単位の一次メッシュ索引 OUTPUT を返す。全検索結果が対象でページングによる欠落なし。概略位置の索引であることを明記。

## 共通条件

QGIS 3.44・4.x、QGIS 付属ライブラリと標準ライブラリのみ。GUI ダイアログやプロジェクト変更を処理本体から行わない。通信処理はバックグラウンド実行可能で進捗・取消に対応。保存済みデータを再利用し、部分取得失敗から全体取得へ自動で切り替えない。JSON は既存の出典・利用条件を維持する。

一時取得は QGIS Processing の一時領域を使用し、別の Processing 呼び出しや結果レイヤーへの所有権移動後もファイルが残る。ブラウザの「レイヤーを閉じたら削除」とは寿命が異なることを説明する。既存のブラウザ保存先も再利用対象とする。

## Shapefile 優先案内（追加）

利用者が承認した一覧の優先表示・推奨情報と説明の組み合わせを採用する。並べ替えだけでは判断理由が伝わらず、強制的な形式置換は明示指定を壊すため採用しない。

`list_resource_files` は部分取得可能な Shapefile を先に返す。同じ優先度の元の順序は維持し、ページングより前に並べ替える。各項目に `recommended`（真偽値）と `recommendation_reason`（非推奨では空文字）を追加する。単体ファイルは比較対象がないため非推奨とする。

推奨は同じ内容なら Shapefile を優先する案内であり、内容の同一性や空間インデックスの存在を保証しない。全候補と明示指定した MEMBER を維持する。説明の冒頭48文字以内に優先方針を含める。空間インデックスの自動作成と Mapsuke 側の変更は含めない。

## 検証

実 HTTP の Range 応答で未選択の大きな ZIP メンバーが全体取得されないこと、付属ファイルの取得、再利用、取消、非対応サーバー、入れ子 ZIP / VRT、実ベクタ・ラスタ・複数サブレイヤー、Mapsuke と同じバックグラウンドタスクからの所有権移動を検証。QGIS 3.44・4.0・4.2、全テストとカバレッジ、Ruff・Bandit・Qt6 互換を確認する。
