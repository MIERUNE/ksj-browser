## User Scenarios & Testing _(mandatory)_

### User Story 1 - データ更新ツールの実行 (Priority: P1)

開発者が学校データの最新版が公開されたときに、国土数値情報の Web サイトから情報を取得してデータコレクション定義ファイルを更新したい。ツールを実行するだけで、手動で Web ページをコピー&ペーストする必要なく、自動的に最新のデータコレクション定義を生成できる。

**Why this priority**: これは MVP の中核機能であり、データ更新の自動化がこの機能の主要な価値提供。手動作業の削減が最も重要な要件。既存の行政区域データ更新ツールと同様の仕組みで学校データを扱えるようにすることで、開発者は効率的にデータを更新できる。

**Independent Test**: ツールを実行し、データコレクション定義ファイルが生成され、Web サイトと同じ内容が含まれることを確認できる。

**Acceptance Scenarios**:

1. **Given** 開発者がプロジェクト環境にいる、**When** データ更新ツールを実行する、**Then** 学校データのコレクション定義ファイルが作成または更新される
2. **Given** 国土数値情報の Web サイトに学校データが公開されている、**When** ツールを実行する、**Then** 定義ファイルには年度ごと・地域ごとのファイル名が正しく格納される
3. **Given** 定義ファイルが既に存在する、**When** ツールを再実行する、**Then** 既存のデータは最新の情報で上書きされる
4. **Given** Web サイトに SHP と GML の両方が掲載されている、**When** ツールを実行する、**Then** SHP が優先的に抽出され、SHP がない場合のみ GML が採用される

---

### User Story 2 - ブラウザパネルでの学校データの表示 (Priority: P2)

QGIS ユーザーがブラウザパネルを開いたときに、既存の土砂災害警戒区域や行政区域データと同様に、学校データもツリー構造で表示され、選択してダウンロード・読み込みできる。

**Why this priority**: スクリプトでデータ定義を生成した後、それを実際に使用できるようにする必要があるが、これは P1 の成果物に依存する。エンドユーザーにとっての価値提供はここで実現される。

**Independent Test**: QGIS でブラウザパネルを開き、KSJ プロバイダーのセクションに「学校」が表示され、年度と地域を選択してデータを読み込めることを確認できる。

**Acceptance Scenarios**:

1. **Given** データコレクション定義ファイルが存在し、表示名が登録されている、**When** ブラウザパネルを開く、**Then** 「土砂災害警戒区域」「行政区域」「学校」がルートアイテムとして表示される
2. **Given** ブラウザパネルで「学校」を展開する、**When** 年度を選択する、**Then** その年度に対応する都道府県リストが表示される
3. **Given** 特定の都道府県を選択する、**When** ダブルクリックまたはドラッグ＆ドロップする、**Then** 該当する学校データがマップキャンバスに読み込まれる

---

### Edge Cases

- Web サイトの構造が変更された場合、ツールはどのように動作するか？（エラーメッセージを表示し、開発者に手動確認を促す）
- 年度や地域のデータが一部欠落している場合はどうなるか？（利用可能なデータのみを定義ファイルに含め、欠落データは警告ログに記録）
- 定義ファイルの形式が壊れている場合、ブラウザパネルはどう振る舞うか？（エラーをログに記録し、該当コレクションをスキップして他のデータは表示を続ける）
- 同じ年度・地域に対して異なるファイル名が存在する場合はどうするか？（最初に見つかったものを使用し、警告をログに記録）
- 同じ年度・地域に SHP と GML の両方がある場合はどうするか？（SHP を優先し、SHP がない場合のみ GML を採用する）
- 学校データのテーブル構造が行政区域データと異なる場合はどうするか？（HTML パーサーロジックを学校データ固有の構造に適応させる）

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: システムは国土数値情報 Web サイトの学校データページから、年度・地域・ファイル名の情報を自動抽出できなければならない
- **FR-002**: システムは抽出した情報を、既存の行政区域データと同じ構造のデータコレクション定義ファイルとして保存できなければならない
- **FR-003**: 開発者はツールを実行するだけで、データコレクション定義ファイルを生成または更新できなければならない
- **FR-004**: ツールは実行時のエラー（Web サイトアクセスエラー、パース失敗など）を適切に報告しなければならない
- **FR-005**: 生成されたデータコレクション定義ファイルは、プロジェクトの適切な場所に配置されなければならない
- **FR-006**: システムは学校データの表示名（例：「学校」）を管理できなければならない
- **FR-007**: ブラウザパネルは、新しく追加された学校データコレクションを、土砂災害警戒区域や行政区域と同じ方法で表示できなければならない
- **FR-008**: ユーザーは学校データを年度・地域で絞り込み、選択したデータを地図に読み込めなければならない
- **FR-009**: ツールは既存の定義ファイルが存在する場合、それを上書き更新できなければならない
- **FR-010**: 生成されたデータコレクション定義の構造は、年度と地域でグループ化され、各地域に対応するファイル名が含まれなければならない
- **FR-011**: 年度・地域に対して複数の配布形式が提示される場合、ツールは SHP を優先し、SHP が存在しない場合のみ GML を採用しなければならない
- **FR-012**: 地域名キーは既存コレクション（行政区域）と同じ表記を用いなければならない（例: `青森`, `東京`, `京都`, `北海道` など、都道府県を示す正規化された文字列）
- **FR-013**: ツールは Web サイトに掲載されている学校データの全ての年度を抽出し、定義ファイルに含めなければならない
- **FR-014**: 学校データのコレクション ID は `gakkou` でなければならない
- **FR-015**: データコレクション定義ファイル名はコレクション ID に一致しなければならない（例: `gakkou` → `gakkou.json`）
- **FR-016**: 学校データの定義ファイルはリポジトリにコミットされ、実行時は同梱されたローカル定義を参照しなければならない
- **FR-017**: ツールは既存の行政区域データ更新ツールと同様の構造とスタイルに従わなければならない
- **FR-018**: ツールはデフォルトで学校データページの URL を参照し、コマンドライン引数でカスタム URL を受け付けられなければならない
- **FR-019**: ツールは明確な終了コード（0: 成功、1: ネットワークエラー、2: HTML 解析失敗、3: ファイル保存失敗）を返さなければならない

### Assumptions

- 国土数値情報の Web サイト構造は、大幅な変更がない限り現在の形式を維持する（ただし行政区域データと学校データでテーブル構造が異なる可能性はある）
- 学校データのファイル名規則は、行政区域と同様の命名パターンに従う
- ツールは開発環境で実行され、必要な依存関係はインストール済みとする
- データコレクション定義ファイルは標準的なテキストエンコーディングを使用する
- ツールはプロジェクト内の適切な場所に配置される
- ブラウザパネルでの表示ロジックは、既存のデータ読み込みとブラウザ表示の仕組みを再利用する
- Web サイト上の地域名表記が異なる場合でも、ツールは既存コレクション表記に正規化できる
- 学校データの URL 構造は、既存の行政区域データや土砂災害警戒区域データと類似しているが、ディレクトリ名規則は個別に調査する必要がある

### Key Entities

- **DataCollection（データコレクション）**: 特定のデータセット（例：学校）を表し、年度ごとの地域別ファイル情報を保持する
- **YearlyData（年度別データ）**: 特定の年度における全地域のファイル情報を保持する（例：「2023 年」の全都道府県データ）
- **RegionalFile（地域別ファイル）**: 特定の地域（都道府県）とそのダウンロードファイル名の対応を表す

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 開発者がツールを実行してから 30 秒以内に、学校データのコレクション定義ファイルが生成される
- **SC-002**: 生成された定義ファイルには、Web サイトに公開されている全ての年度と地域のデータが含まれ、データの欠落率が 0%である
- **SC-003**: ブラウザパネルで学校データを選択してから 5 秒以内に、地図キャンバスにデータが表示される
- **SC-004**: 手動でのデータ定義更新作業が 100%削減され、開発者はツール実行のみで最新データに対応できる
- **SC-005**: エンドユーザーは、土砂災害警戒区域や行政区域と同じ操作感で学校データを利用でき、操作方法の学習コストが発生しない
- **SC-006**: ツールは既存の行政区域データ更新ツールと同等の信頼性とエラーハンドリングを提供し、異常終了時には明確なエラーメッセージと終了コードを返す
