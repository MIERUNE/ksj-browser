# 配布データのローカル保存

> 初版の設計記録です。ZIPの保存・参照方式は、後続の[展開済みファイル方式](2026-10-22-extracted-files-design.md)へ変更しました。

## 目的と承認済みの動作

国土数値情報の配布ファイルを、初回に選択した保存先へダウンロードしてから表示する。保存先はQGISの利用者設定に記憶し、別プロジェクトでも再利用する。保存先の変更はブラウザの右クリックから行う。ZIP内の選択、ドラッグ、メッシュからの追加を維持する。

## 方式の比較

- **初回選択・記憶（採用、利用者承認済み）**: 保存場所を利用者が決め、通常の操作では再設定しない。
- 既定フォルダへ自動保存: 設定不要だが保存場所が分かりにくい。
- プロジェクトごとの保存: 共有しやすいが、繰り返し設定・取得が生じる。

## 実装方針

- 配布URLごとに保存パスを分け、同名の異なる配布を混同しない。
- ダウンロードはQGISのネットワーク機能でファイルへ逐次保存する。大容量ZIPをメモリに全展開しない。
- 一時ファイルを検証してから完成ファイルへ置き換える。失敗・中止した途中ファイルは使わない。同じ保存先・URLへの同時取得はロックで抑止する。
- ZIPは展開せずローカルの `/vsizip/` から読む。単体ファイルもローカルパスから読む。プラグインの新規レイヤー参照には `/vsicurl/` を使わない。
- 初回のブラウザ展開では保存先選択の項目を提示する。フォルダ選択などのUIはGUIスレッド、ダウンロードはブラウザのワーカーまたは既存のメッシュタスクで実行する。
- 保存先変更は今後の取得へ適用し、既存レイヤーや保存済みファイルは移動しない。自動更新・自動削除は行わない。

## 範囲と制約

Python 3.9以上、QGIS 3.40以上、Qtは `qgis.PyQt` 経由、追加依存なし。説明は日本語とする。旧プロジェクトのリモート参照は自動変更しない。共有時はプロジェクトと保存データを併せて渡す。今回検証できる環境はQGIS 3.42.1 / Qt 5.15.2である。

## 検証

ローカルHTTPサーバーで取得回数を数え、再利用・同時取得・失敗・中止を確認する。ブラウザとメッシュ経路でローカルURIを検証し、プロジェクト保存・再読み込み後も通信なしで地物が読めることを確認する。回帰テスト、カバレッジ、Ruff、UI表示を確認する。
