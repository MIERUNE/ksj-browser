# メッシュ索引からのデータ追加

## 目的と仕様

道路などの配布メッシュ番号だけでは場所を選びにくいため、地図上の範囲から配布データを選択できるようにする。

- ブラウザの年度の右クリックから索引を追加する。メッシュ配布がない年度には表示しない。
- カタログに配布がある1次メッシュだけを、透明な塗りつぶし・青い枠・メッシュ番号で表示する。
- 同一メッシュの複数形式や測地系、河川などの配布違いを保持する。クリック時に配布ファイルを選択し、含まれるレイヤーを追加する。
- QGIS 標準の地物アクションを使用し、索引追加時にツールを有効にする。追加完了後も索引をアクティブに戻す。
- 索引は GeoJSON 文字列をデータソースとしてプロジェクトに内包し、外部一時ファイルに依存しない。
- ZIP走査とGDALによるレイヤー列挙をバックグラウンドで実行し、地図への追加はGUIスレッドで行う。
- 同じ配布への連打・レイヤー重複を防ぎ、部分削除・読み込み失敗から再試行できる。
- 索引削除・プラグインのアンロードで実行中タスクを取り消す。古いコールバックが新しいタスクを消費しない。

現行の同梱カタログで数字のみの配布地域はすべて4桁（18,850配布）であった。1km・500mなどのデータ内の細分メッシュではなく、配布単位の1次メッシュを扱う。索引は世界測地系の位置案内で、旧日本測地系の厳密な境界を再現する用途ではない。

区画の計算は[総務省統計局の地域メッシュの説明](https://www.stat.go.jp/data/mesh/m_tuite.htm)に基づく。4桁コードの上2桁から南端緯度を `値 × 2/3`、下2桁から西端経度を `値 + 100` とし、緯度40分・経度1度のポリゴンを作成する。

## 検証環境

- macOS、QGIS 3.42.1、Qt 5.15.2、QGIS付属Python 3.9.5。
- QGIS 4 / Qt 6 での実機検証は行っていない。
- QGIS のアクション・タスク仕様は Context7 の公式QGISドキュメントとローカルの実APIで確認。

## 自動テスト

`tests/test_mesh_index.py` で実QGIS・実OGRレイヤー・ローカルZIPを使用する。

- 年度のアクションを実行し、同じメッシュの3形式が1ポリゴンになることを確認。
- 東京の `5339` が東経139–140度、北緯35度20分–36度となることを確認。
- QGZ保存・再読込後、保存された地物アクションを式展開して実行し、選んだメッシュだけを追加。
- 一部レイヤーの削除後、既存レイヤーを重複させずに復旧。
- キャンセルしたタスクの遅いコールバックと、新しい同URLタスクの競合を検証。
- GDALの例外設定の有効・無効にかかわらず、説明用XMLを読み飛ばし、壊れた空間データは失敗として保持。
- 無効な追加済みレイヤーがあっても再試行できることを確認。
- 実際のQtダイアログで2番目の配布の選択・キャンセルを検証。
- 通信失敗の通知と再試行、索引削除・アンロード時の遅延追加防止を検証。

実行コマンド:

```bash
source setup_qgis_env.sh
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q --cov=ksj --cov=scripts --cov-report=term-missing
uv run ruff check .
git diff --check
```

最終結果: **99 passed**。`ksj/mesh_index.py` のカバレッジ85%、`ksj` と `scripts` の全体83%。Ruff と差分の空白検査も成功。警告は既存の pytest-cov フックの非推奨通知2件と uv 設定の非推奨通知で、テスト失敗はない。

## 実配布・GUIでの確認

道路2024年の全480配布を160メッシュにまとめ、カタログ内の全メッシュ番号との一致と、全ポリゴンの幾何学的な有効性を実QGISで確認した。

公式カタログの道路2024年 `N13-24_3622_GEOJSON.zip` を新しい読み込み経路で取得し、有効なラインレイヤー `N13_25_3622`、800地物を確認した。配布年度と内部レイヤー名の年表記は公開ファイルのまま保持する。

QGISの実画面でも3622・3623の索引を表示し、3622をマウスでクリックした。3形式の選択ダイアログでGeoJSONを選び、道路レイヤーが追加され、「1レイヤーを追加しました」と表示されることを確認した。索引がアクティブに戻り、青いメッシュ枠と番号が表示された。

実データの読み込みに資格情報は不要。ターミナル検証では既存の開発手順どおり `CURL_CA_BUNDLE=/etc/ssl/cert.pem` を使用した。
